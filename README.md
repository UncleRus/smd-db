# SMD-DB

Веб-интерфейс поиска по базе SMD-деталей. Одна страница поиска с фильтрами,
отдельная страница детали и страница «О базе». Интерфейс на английском,
русском и китайском; три темы оформления (iron / neon / dust).

Приложение построено на **CherryPy** (WSGI-фреймворк) и **Jinja2** (шаблоны).

Данные и оформление — из исходных материалов без изменений:

- `smd.sqlite` — копия `materials/smd.sqlite`, открывается **только для чтения**;
- `app/static/elumkit/` — байт-в-байт оригиналы дизайн-системы elumkit
  (`packages/core-css/src`). Собственные стили приложения лежат отдельно в
  `app/static/app.css` и подключаются **после** elumkit.

## Требования

- Python 3.11+
- Зависимости рантайма из `requirements.txt`: CherryPy 18.10+ и Jinja2 3.1+.
  Сервер cheroot входит в состав CherryPy.

## Запуск

```bash
cd build
python3 -m venv .venv                     # если .venv ещё нет
./.venv/bin/python -m pip install -r requirements.txt
./.venv/bin/python run.py
```

Приложение поднимается на <http://127.0.0.1:5000/> (cheroot WSGI-сервер).
Остановить — `Ctrl+C`.

## Тесты и проверки качества

```bash
cd build
./.venv/bin/python -m pip install -r requirements-dev.txt   # pytest, mypy, ruff, black
./.venv/bin/python -m pytest        # 34 теста
./.venv/bin/python -m mypy          # mypy --strict, конфигурация в pyproject.toml
./.venv/bin/python -m ruff check app run.py tests
./.venv/bin/python -m black --check app run.py tests
```

Тесты работают без запуска сервера: `create_app()` возвращает обычный
WSGI-callable, который тестовый клиент дёргает напрямую.

## Маршруты

| Метод | Путь                          | Назначение                                   |
|-------|-------------------------------|----------------------------------------------|
| GET   | `/`                           | Поиск и результаты                           |
| GET   | `/part/<int:part_id>`         | Страница одной детали                        |
| GET   | `/package/<path:code>/image`  | PNG-чертёж корпуса (BLOB из БД)              |
| GET   | `/about`                      | Страница «О базе»                            |
| GET   | `/static/...`                 | Статика (elumkit, `app.css`, `app.js`)       |

## Страницы ошибок

Стандартные страницы ошибок CherryPy переопределены
(`error_page.default` → `controllers.error_page`). Любая ошибка — 404
неизвестного маршрута, отсутствующей детали, корпуса или файла статики, а
также внутренняя ошибка 500 — выводится на странице `error.html`: тот же
navbar, тема, язык, футер и оформление elumkit, что и у остальных страниц.
Код ответа (`404`/`500`) сохраняется, трейсбек пользователю не показывается.
Текст локализован (EN/RU/ZH) и берётся из текущей сессии/параметров запроса.

## Параметры поиска (`/`)

Все параметры хранятся в URL, поэтому ссылка на результаты адресуема.
Пока не задано **ни одного** условия, таблица результатов не выводится —
страница показывает форму и подсказку начать поиск; полный каталог не
выгружается.

| Параметр       | Значение                                                      |
|----------------|---------------------------------------------------------------|
| `code`         | Маркировка (подстрока, регистр не важен; спецсимволы — буквально) |
| `name`         | Название (подстрока, регистр не важен)                        |
| `function`     | id функции                                                    |
| `manufacturer` | id производителя                                              |
| `package`      | код корпуса                                                   |
| `pins`         | число выводов                                                 |
| `sort`         | `marking` \| `name` \| `manufacturer` \| `package`            |
| `per`          | размер страницы: 20 \| 50 \| 100                              |
| `page`         | номер страницы                                                |
| `lang`         | `en` \| `ru` \| `zh`                                          |
| `theme`        | `iron` \| `neon` \| `dust`                                    |

Язык и тема сохраняются в серверной сессии CherryPy, поэтому после перехода
без параметров выбранное оформление и язык сохраняются.

## Замечания по данным

- Поиск по маркировке — по **подстроке** кода и без учёта регистра: `L3`
  находит 753 записи (полное совпадение дало бы 60).
- Спецсимволы в кодах (`?`, `+`, `/`, `\`, `_`, `%`, `*`) трактуются
  буквально, а не как маски `LIKE`/`GLOB`: `%` — это подстрока в 6 записях,
  а не «все строки».
- FTS не используется: фильтры по `LIKE` и точному совпадению по 423 489 строкам
  укладываются в десятки миллисекунд, а схема БД при этом не меняется.
- Соединения с базой кэшируются на поток и переиспользуются; база всегда
  открывается в режиме `mode=ro` с `PRAGMA query_only = ON`.
